# 手机放远之后：先验证一段可听懂的行进

日期：2026-11-17。状态：交互验证方案与原创声音脚本，尚未录音或实机运行。

## 推荐先解决的问题

景观再好，用户运动时也不能一直盯着手机。建议把运动中的乐趣主要放在“我知道在做什么、身体活动有回应、目的地越来越近”，在自然停顿交付值得靠近看的风景。整段行进不靠连续旁白填满。

这里建议增加一个待审阅选择：**首版评估计时跟练模式，与相机反馈分别验证。** 跟练按课程引导与用户确认推进，清楚记录为跟练时长；相机模式只把实际识别结果记为识别结果。两者都不自动证明动作标准或训练效果。

理由是丰富动作库、不同空间与不愿授权摄像头的用户，都可能需要其他接入方式。这个选择会改变冻结稿中尚未确定的无摄像头能力范围，因此作为新增建议单列，不视为已确认，也不表示已有实现。

## 两种方式如何比较

| 项目 | 相机反馈候选 | 计时跟练候选 |
| --- | --- | --- |
| 开始前 | 需要授权、摆位和候选动作试做。 | 需要学会动作、确认实际准备条件。 |
| 运动中 | 对可信识别的小段或组次反馈；不确定时如实提示。 | 按已经确认的课程计时引导，小组完成可由用户确认。 |
| 冒险进展 | 根据当前课程对应的小目标推进。 | 根据跟练阶段及确认推进，不宣传动作已被验证。 |
| 结果 | 区分已识别、引导和恢复时间，不能把未识别直接推定为没运动。 | 展示引导活动和用户确认，不能伪造成识别计数。 |
| 需要验证 | 摆位成本、漏计、延迟及反馈是否可信。 | 能否保持投入、是否理解动作、反馈是否足以激励。 |

没有排行榜的单人首版不必先以防作弊作为主要设计目标。需要验证的是用户是否愿意认真完成课程，以及相机反馈能否增加价值。若相机效果不合格，不能用加做动作补齐漏计来掩盖问题。

## 三分钟声音脚本样段

这是已经完成热身、处于适用课程中的一段交互示例，**不是可直接照做的三分钟训练处方**。动作、剂量与恢复仍来自审阅后的课程。具体秒数是脚本位置，不规定用户必须在该时刻达到某个运动量。

| 位置 | 当前任务 | 原创声音示例 | 屏幕和反馈 |
| --- | --- | --- | --- |
| 段落开始 | 交代本段目标。 | “前面是歇脚处。先按刚才学过的节奏踏步，这一小段我们只做这一件事。” | 当前动作与暂停入口清楚，画面稳定。 |
| 活动开始后 | 让活动有回应。 | 只有可信识别时给简短确认：“对，就是这个节奏。”跟练版可用“按你的节奏继续”，不冒充识别。 | 环境声和节奏层轻微建立；不要求读文字。 |
| 第一小段完成 | 给出阶段成果。 | “这一小段完成了。先放慢，听前面的风声。” | 按课程进入恢复，进度与实际来源分别记录。 |
| 可以观看时 | 交付关键景观。 | “到了。准备好再看看眼前的山脊。” | 景观等待用户，可靠近手机或延长停留；不自动切走。 |
| 恢复结束、用户准备好 | 处理一件具体选择。 | “背包里还有两块巧克力。现在用一块，还是留到营地？” | 仅在安全停顿展示两个大选项与库存变化。需要时间就暂停。 |
| 用户选择后 | 回应选择、建立期待。 | 留存版：“那就留给营地。接下来按你的课程继续，前面还有一段路。” | 选择只改变虚拟物资与故事，不提高真实训练负荷。 |
| 再次开始 | 回到身体任务。 | “先回到合适的位置。准备好了，再开始下一段。” | 相机模式重新确认可用位置；跟练模式等待用户开始。 |

完成反馈不需要每一步都说话。优先比较较安静和较丰富的环境反馈，观察用户能否知道当前任务、有无被打断，以及是否期待下一处景观，再决定密度。

## 手机摆放的操作边界

不预设所有手机都在同一高度、距离或角度识别成功，先用实际设备与动作验证。开始前找到稳定位置；站姿、坐姿、地面和器材动作分别检查。

靠近手机观景或做选择时，本段已经进入相应停顿；走近设备不能误计为训练动作。若用户移动手机，相机模式应在继续前重新确认画面，恢复不从头重复已完成小段。

电视或投屏可以后续改善观看，但首轮必须在只有一部手机时检验体验。不能把外接大屏作为核心流程成立的前提。

## 如何做首次验证

1. 先让参与者看懂预览、动作教学和暂停方式，再试一段经审阅的短课程。
2. 用同样景观和课程比较相机候选与跟练候选；纸面或人工触发时明确标为人工模拟。
3. 记录准备与重摆次数、主动看屏原因、漏听指令、反馈误解、退出原因和段落后用力感。
4. 询问下一段想去哪，并观察是否主动发起下次体验，而不只收集“画面好看”的评价。

课程适用性和实际参与安排需另行准备。本轮只形成验证方案，没有参与者、录音样片、识别准确率或满意度结果。
