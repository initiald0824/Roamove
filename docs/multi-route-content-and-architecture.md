# 多路线内容与可扩展架构原则

更新日期：2026-11-17。

用户已明确：当前以鳌太线作为首张地图，后续接入更多真实路线并持续更新，整体产品设计、代码架构和实现都必须支持扩展。本文记录后续设计与实现的约束；职责划分、内容组织及更新方式是当前建议，技术栈与具体接口尚未确定，当前不编写实现代码。

## 产品长期结构

Roamove 包含共用的用户适配与训练能力、冒险运行能力，以及持续增加的路线内容。鳌太线作为首张地图验证这些能力，水窝子作为完整体验样板。18 个站点组是鳌太线的候选资料，不是所有地图的固定节点数量或系统结构。

未来路线可以具有不同站点数量、拓扑、景观、故事和可用玩法。按需组合已支持的露营、观景、物品与返程等能力，保留每张地图的内容特点。下一张路线、上线数量、更新频率和具体订阅权益仍待产品讨论。

## 共用能力与路线内容的边界

以下是职责边界，首版可在同一个本机 App 中实现。

| 部分 | 负责什么 | 与具体地图的关系 |
| --- | --- | --- |
| 用户资料与训练历史 | 活动能力、限制、偏好、当天状态及实际运动记录。 | 跨地图共用，切换路线不会重置用户情况和近期训练负荷。 |
| 动作库与训练编排 | 动作、变式、适用条件、组次、恢复与个性化安排。 | 独立于地名和路线剧情；具体规则沿用用户适配设计。 |
| 冒险运行 | 站点连接、行程、分支条件、物品变化、事件与阶段进度。 | 执行已支持的通用规则，读取当前路线的内容和配置。 |
| 动作引导与识别 | 示范、声音指令、计时或识别计数，以及活动结果。 | 按动作和本次训练工作，具体识别方案可替换，不依赖鳌太线。 |
| 画面与声音呈现 | 第一人称风景、环境声音、事件演出与训练反馈。 | 根据内容引用加载素材，媒体形式及播放规则与路线资料分开。 |
| 内容获取与校验 | 路线目录、版本、资源准备、完整性和能力兼容检查。 | 对每张地图采用相同的内容约定，支持后续按需获取。 |
| 存档与权益 | 用户记录、每条路线的冒险进度、内容版本与可用权益。 | 共享用户资料，每张地图及每次远征有明确归属；权益政策另行决定。 |

地图可以提出段落的训练主题和叙事节奏，例如持续行进或一段起伏；用户实际执行的动作与运动量由训练系统按个人条件安排。新增路线不能绕过用户限制，直接写入所有人必须完成的固定运动量。虚拟地理距离与真实运动记录分别处理。

## 每张地图作为独立内容包组织

内容包是资料与素材的组织单位，具体文件格式和拆包方式后续确定。通常应包括：

- **路线资料：** 稳定标识、名称与简介、封面、地区信息、内容版本及所需 App 能力。
- **站点与连接：** 节点、可选行程、方向、进入和退出条件，以及不同到达方式的内容引用。
- **关卡内容：** 运动段落的主题、观景点、事件、分支、收尾与可用玩法。
- **旅途物品：** 引用共用物品定义，配置本路线使用的物品、起始数量和情景规则。
- **训练衔接：** 引用共用训练模板或描述段落需要，交由用户适配与训练编排处理。
- **画面与声音：** 场景、短片、图片、环境声和演出的引用及资源信息。
- **本地化内容：** 各语言的标题、说明、故事、字幕与音频引用，支持语言范围另行确定。
- **生产资料：** 地理资料依据、虚构内容标记、素材来源与授权记录。

主要通过新增路线资料、素材和已支持规则的配置扩展地图。新动作识别方式、全新互动或新的呈现能力需要程序支持，纳入 App 版本开发。内容配置只表达已经支持的规则和素材引用。

## 标识和状态需要从第一版区分

| 数据 | 建议约束 |
| --- | --- |
| 路线、站点、行程与事件 | 使用稳定标识，避免依赖中文名称、列表序号或固定站点数量；地图内标识具备路线归属。 |
| 用户资料、实际运动历史 | 跨地图保存，可引用来源路线和关卡；地图改名、换素材或删除下载内容不会删除运动历史。 |
| 冒险进度 | 明确所属路线、内容版本和本次远征，包括位置、分支、角色状态与已发生的物品变化。 |
| 收藏与到达记录 | 与当前运动会话分开，更新路线内容时保留已经取得的成果。 |
| 素材缓存 | 与存档分开，删除或重新下载地图素材不会清空用户进度。 |

地图切换时如何展示多个未结束的远征、背包是否跨地图继承等，属于后续玩法决策。存储设计先能明确区分这些状态，避免提前混为一个全局当前位置或背包。

## 持续更新与离线体验

首版沿用核心本机运行、按需联网、暂不自建业务服务器的方向。内容可以先随 App 提供；后续采用资源托管、按需下载的具体方案和费用，依据素材体量与发行方式另行核实。

内容更新建议区分三件事：内容格式是否兼容、当前 App 是否具有所需能力、具体地图内容是哪一个版本。动作与适配规则也需要独立版本记录，不能随地图更新被无记录地覆盖。

建议的更新约束：

1. 新内容在投入使用前检查结构、站点引用、资源完整性及所需能力；不满足条件时给出清楚提示。
2. 新版本准备完整后再切换，下载中断或校验失败时保留原先可用版本。
3. 正在进行的关卡固定其内容版本，避免运动中途改变剧情、物品或训练要求；切换时机和训练恢复方式后续细化。
4. 更换或删除节点时明确处理旧标识和存档迁移。兼容方式未确认时保留旧进度及必要内容，用户的运动历史与收藏继续可查看。
5. 素材清理检查活动关卡和存档的依赖，避免删除仍需使用的版本。
6. 已准备好素材和有效可用权益的内容继续以离线体验为目标，首次下载、更新和购买等在线流程分别设计。

新增路线和订阅权益的关系采用独立配置，避免在地图名称里隐含免费或付费规则。免费覆盖范围、权益变化、离线权益策略和内容停止提供时的用户体验仍需讨论。

## 新路线的制作与接入流程

建议按统一内容约定组织：路线资料核实 → 节点与连接设计 → 剧情和训练段落衔接 → 素材及本地化制作 → 内容与训练适配检查 → 真机体验验证 → 发布。

检查项目应包含真实地点与虚构事件的区分、分支能否正确抵达或退出、物品变化和暂停恢复、素材质量与来源、不同用户训练版本，以及语言内容是否齐全。内容格式和校验工具随实现阶段确定。

首版用鳌太线实现这些边界，并在设计评审时用一条不同节点数量、具有不同玩法组合的假想路线检验接入过程。这个检验不表示已选择第二张正式地图或增加其素材制作范围。

## 后续实现的验收要求

- 用已有能力接入新地图时，主要改动应集中在路线资料、素材与配置，共用训练和识别逻辑保持复用。
- 新地图可以有不同节点数量、分支结构和玩法组合，核心逻辑不依赖鳌太线地名、18 个节点或固定连线。
- 同一地图适配不同用户，同一用户切换地图后保留个人限制、偏好、训练历史与恢复信息。
- 更新地图素材或故事后，已经完成的运动、收藏与可恢复的冒险进度得到明确保留或迁移。
- 下载失败、能力不兼容、删除素材及离线进入都有明确的可用状态与恢复方式。
- 新语言通过本地化内容接入，界面和训练逻辑不依赖特定语言的文本。

这些要求在实现阶段通过相应检查和测试验证，目前仅形成架构与内容设计约束。
