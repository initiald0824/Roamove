# 首版范围与完整用户流程草案

更新日期：2026-11-17。

当前已经有水窝子体验脚本、营地分支、物资装备和第一人称视觉示意。用户希望先有示意、细节逐步打磨，并进一步明确健身是核心、训练需要结合个人情况与丰富动作库。当前先讨论[用户评估与动作适配](personalization-and-movement-library.md)、[训练编排](movement-and-training-design.md)，再据此细化首版整体体验和用户流程。本文提供讨论用建议，正式关卡数量、免费与订阅边界、页面划分和交互仍待确定，当前继续产品讨论。

## 这一步要形成什么

明确用户第一次打开后怎样开始，运动过程中怎样知道进展、暂停与恢复，结束后得到什么，以及下次打开怎样接上旅程。由这条流程确定必要页面、状态与首版内容范围，再细化每一步。

水窝子是当前体验样板，用于推敲一段完整冒险；它不自动成为正式首发第一关。正式起点、覆盖节点与素材范围需要另行决定，18 个候选站点仍作为节点池。

用户已明确鳌太线作为首张地图，后续持续增加路线。流程长期预留路线目录、内容准备与切换入口；用户资料和运动历史跨地图共用，每张地图的冒险进度有明确归属。首版可以先围绕一张地图呈现，具体入口和切换方式按[多路线架构原则](multi-route-content-and-architecture.md)继续细化。

## 首版核心体验建议

| 部分 | 当前建议 | 仍待明确的内容 |
| --- | --- | --- |
| 进入体验 | 单人、本地体验，打开后能够快速找到开始或继续的入口。 | 首次引导长度、默认推荐目的地与正式起点。 |
| 了解用户 | 用必要信息了解目标、运动基础、活动能力、限制和环境，之后确认当天状态。 | 问题、必填范围、适配规则及可支持的人群范围。 |
| 一次冒险 | 按明确训练目的组织约 20 分钟体验，安排热身、主训练、恢复和放松，以第一人称风景与事件承接。 | 训练重点、动作、组次与节奏、替代方案、识别与素材形式。 |
| 旅途选择 | 选择有连接关系的目标，在停顿时作出当前有关的决定。 | 首版节点数量与连线，以及每种选择的可玩内容。 |
| 物资和装备 | 少量具体食物和水、默认基础装备，一条角色体力槽。 | 数量、消耗、恢复和取得方式。 |
| 暂停与保存 | 随时暂停或结束，保留已完成进度和发生过的物品变化。 | 退出、再次进入、跨日恢复的完整体验与保存粒度。 |
| 抵达与再次出发 | 记录到达、景观和实际活动，预告下一次值得体验的内容。 | 旅途册的呈现、继续与重玩入口。 |
| 免费与订阅 | 免费体验加订阅已确定；先提供一段能感受到完整价值的体验是当前建议。 | 免费覆盖哪些内容、何时介绍订阅、具体权益与价格。 |

首版以本机运行、按需联网和暂不自建业务服务器推进。社交、云存档、好友榜是否纳入首版仍待讨论，不能由托管服务费用低就推定全部需要接入。现阶段可将旅途卡分享作为轻量候选。

## 从第一次打开到再次回来

以下是用户流程的工作版本，页面可以合并；先看每一步是否清楚、必要、容易完成。

| 阶段 | 用户看到或做什么 | 这一步需要交付什么 |
| --- | --- | --- |
| 1. 第一次打开 | 第一人称景观预览、简短说明，以及清楚的开始入口。 | 知道这是用身体推进的自然冒险，并愿意开始一段体验。 |
| 2. 了解用户情况 | 首次提供必要的目标、基础、活动能力、限制与环境信息；已有资料时确认变化和当天状态。 | 能依据用户情况选择训练；信息不足或不具备安排条件时有清楚的后续说明。 |
| 3. 确认本次目的地 | 看到本次目标、约需时长和景观预告，可查看路线位置。 | 知道今天要到哪里，以及到达后会获得什么。 |
| 4. 出发准备 | 预览适配后的训练重点、实际动作及恢复安排，调整强度或替代方案，再查看默认食物与基础装备。 | 明白本次实际运动安排与虚拟旅途条件，快速完成准备。 |
| 5. 摆位与动作试做 | 在进入识别前了解相机用途、授予权限，按示意摆放手机，尝试适合本次安排的动作。 | 确认能够被识别或理解当前引导方式，知道怎样获得反馈和暂停。 |
| 6. 行进与停顿 | 按本次适配后的安排完成短段运动、观景与事件。 | 通过声音知道当前任务、动作反馈、阶段进展和何时可以停下。 |
| 7. 暂停或提前结束 | 随时暂停、保存或收尾；恢复时确认当前状态、任务与摆位，再继续。 | 用户能处理现实中的打断，并清楚已完成内容保存到了哪里。 |
| 8. 抵达与结算 | 先交付目的地风景，再记录到达、实际活动、见闻和物品变化，收集本次运动感受，选择保存、停驻或安排后续。 | 今天的一段体验完整成立，后续训练可参考反馈，下一段运动由用户另行主动开始。 |
| 9. 下次打开 | 看到上次停留处、保存进度和一个明确的继续入口，同时确认当前状态并预览后续景观。 | 能迅速接上旅程，知道这次继续有什么期待。 |

水窝子已有[约 20 分钟体验脚本](aotai-shuiwozi-20-minute-walkthrough.md)，用于参考声音与内容节奏；下一版需按个人训练安排重排。本表不预设新用户已经完成其他站点，新用户正式出发的起点与教学方式另行讨论。

首次问题已收敛为[精简评估 V1](first-assessment-v1.md)的三个主问题与按需补充。三个主问题及各自跳过入口均已确认，活动限制多选页具体选项仍为候选。[用户适配草案](personalization-and-movement-library.md)保留完整信息范围及水窝子不同用户版本的检查方向，再据此细化页面与交互。

当前用[水窝子训练预览页 V1](aotai-shuiwozi-training-preview.md)逐项打磨具体内容与交互：先明确顶部的目的地与参考时长，再讨论训练重点、动作、强度和必要准备，“准备出发”后进入摆位与动作试做。多选页具体选项仍待确认，不因进入下一环节而视为已确定。

## 第一屏的初步建议

以一个清楚的主入口开始：第一人称景观预览、本次推荐目的地、约 20 分钟的提示和“开始冒险”。已有存档时，主入口优先显示“继续旅程”，同时说明将从哪里接上。

路线地图和背包详情可展开查看。第一轮先讨论主入口与目的地选择的关系：是直接推荐一段体验，还是让用户先在地图上挑选。当前倾向首次有明确推荐，后续逐步展开路线选择。

这一建议尚未确定具体页面样式。手机横竖屏与摆位、全身入镜和观景体验一起验证，再确定页面布局；现有宽幅概念图仅用于视觉示意。

## 免费体验与订阅怎样接入流程

当前建议让用户先经历一次有出发、运动、看景和收尾的完整小冒险，再在结算或选择后续内容时介绍订阅能够带来的价值。

免费体验覆盖几关、是否使用独立体验章节、哪些高级功能属于订阅权益仍待决定。水窝子内部样板不代表已经确定免费范围，也不表示上架版本只需这一关。

可点击的目的地对应已经完成的可玩内容，尚未制作的站点用清楚的后续预告表达。首版应交付多少内容、怎样支撑持续订阅，需要在范围讨论中单独推敲。

## 异常与恢复也属于完整体验

- 首次摆位或识别不顺利时，可以继续调整、使用已设计的替代动作或先退出；相应页面与提示需要能解释当前情况。
- 暂停或退出时，冻结虚拟时间与状态，保存已完成进度和已确认的物品变化；保存粒度与再次进入的恢复方式待明确。
- 恢复时先说明所在阶段，确认摆位与准备情况，再主动继续，避免直接进入运动要求。
- 现实中的提前结束保留实际活动，角色下撤可以叙事收尾；游戏结局和实际运动记录分别展示。

首次教学与摆位可能比常规准备更久，时间承诺需通过实际体验确认。约 20 分钟继续作为单关参考节奏，首次引导、暂停与延长停留分别说明。

## 后续推进顺序

1. 先明确用户评估与适配规则，扩充候选动作，确定个人训练重点、强度和恢复安排，以水窝子推演不同用户的完整体验。
2. 据此讨论第一次打开到真正开始运动的流程，确定推荐入口、目的地确认、权限和摆位怎样衔接。
3. 串起暂停、结算和下次继续，明确首版必要页面、保存规则与内容范围，再细化免费体验、订阅权益及首版地图覆盖。
4. 通过实际试做与原型验证训练编排、摆位、动作反馈和短段落趣味，当前视觉示意即可支持这一轮讨论；美术细节和完整内容制作随验证结果打磨。

这一阶段的判断重点是：训练目的和实际完成是否清楚，运动安排是否适合目标用户，用户是否容易开始、能否舒服地完成一段冒险，以及结束后是否满足并期待下次出发。
